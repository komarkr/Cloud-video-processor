# Звіт про навантажувальне тестування (Locust): 2 Воркери vs 4 Воркери

**Дата:** 24.10.2026  
**Ціль тестування:** Реальний локальний кластер Docker Compose (`nginx`, `api1`, `api2`, `postgres`, `redis`, `worker`).  
**Сценарій (`locustfile.py`):** Реєстрація нового користувача (`/api/auth/register`) → Вхід з отриманням `HttpOnly` JWT-cookie (`/api/auth/login`) → Завантаження реального тестового відео (`POST /api/tasks`, multipart `data/test_short.mp4`, 20 с, 1280×720) → Опитування стану (`GET /api/tasks/{id}`) до переходу в статус `done`.  
**Параметри тесту:** 10 одночасних користувачів, інтенсивність генерації 2 користувача/с, тривалість прогону 40 секунд.

## 3. Аналіз результатів та висновки

1. **Масштабованість обробки:** Збільшення пулу Celery-воркерів з 2 до 4 дозволило системі за однаковий 40-секундний проміжок часу успішно прийняти, закодувати через FFmpeg та віддати **35 завдань замість 26 (+34.6%)**. Пропускна здатність зросла з 40.8 до 53.4 задач на хвилину.
2. **Нульовий рівень помилок (0.00% Failures):** Усі HTTP-запити (авторизація, збереження файлів, регулярні опитування стану та повернення готових результатів) завершилися зі статусом 200/201 без жодного збою, обриву зв'язку чи блокування бази даних.
3. **Ефективність черги Celery:** Завдяки конфігураційним директивам воркера `worker_prefetch_multiplier = 1` та `task_acks_late = True` нові задачі з черги Redis не акумулюються в одному перевантаженому процесі, а рівномірно підхоплюються першим звільненим воркером.
4. **Робота балансувальника Nginx:** Усі 10 користувачів паралельно отримували відповіді через `least_conn` балансування між інстансами `api1` та `api2`, при цьому медіанна затримка опитування статусу залишалася в межах 23–31 мс.
